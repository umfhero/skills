# UEFN MCP — First Run Findings (2026-08-20)

The original session that prompted this knowledge base: building a solo tycoon in a fresh
UEFN project (`MCP_KFMAP`) through the official UEFN MCP server, entirely via an AI agent.
These are the raw, first-hand findings from that run. They complement the web research in
`../research/` and the automated capability test in `../tests/`.

## 1. Environment as observed

- Editor: `UnrealEditorFortnite-Win64-Shipping` (PID 36028).
- Project: `C:\Users\umfhe\Documents\Fortnite Projects\MCP_KFMAP`
  - `.uefnproject` had `bEnablePythonForProject: true`, toolsets enabled, scene graph enabled.
- MCP server confirmed at `http://127.0.0.1:8000/mcp` (user-verified: path `/mcp`, port `8000`, auto-start ON).
- Server responds to `initialize` with protocol `2025-06-18`; `serverInfo` is **empty** (name/title/version blank).

## 2. Protocol behaviour observed

- Every request after `initialize` needs the `Mcp-Session-Id` header; without it the server
  returns `-32600 Missing required Mcp-Session-Id header for 'tools/list'`.
- Session IDs are 32-hex strings, e.g. `06999bde488e51bdecd0da86a9c05dce`,
  `139dc83e466c2d4915b215865cdf0b5f`. Each new `initialize` mints a fresh session.
- Tool-search mode is ON: `tools/list` returns only the meta-tools
  `list_toolsets` / `describe_toolset` / `call_tool`.
- Responses came back as plain JSON (not SSE lines) via curl in this mode.
- `resources/list` → empty; `prompts/list` → `-32601` (not implemented).

## 3. Transport gotchas (critical for any future agent)

- **Use `curl.exe`, not PowerShell `Invoke-WebRequest`/`RestMethod`** — they fail
  non-interactively in this environment.
- Write each JSON-RPC body to a temp file (ASCII encoding), then
  `curl.exe -s -X POST http://127.0.0.1:8000/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -H "Mcp-Session-Id: <id>" --data-binary "@body.json"`.
- **Never issue parallel MCP calls** — the server serialises on the game thread; parallel
  calls caused corrupted temp files / confusion.
- **"Invalid JSON body!" (`-32700`) workaround:** usually means a documented optional
  argument is being passed with the wrong shape (or null). Retry by OMITTING that field:
  - `PrimitiveTools.add_cube` → omit `dimensions` (default 100cm cube).
  - `EditorAppToolset.SetCameraTransform` → omit `scale`.
  - `CaptureViewport` → omit `annotations` entirely (broken in every shape tried).
  - `ObjectTools.get_properties` → only pass property names that exist on the object
    (check `list_properties` first).

## 4. What was actually built in the first run

1. **Material** `/Game/M_Block_Red.M_Block_Red`:
   - `MaterialTools.create_material` → `get_statistics`/`get_expressions`.
   - Added `MaterialExpressionConstant3Vector` node, set `constant` = r1 g0 b0 a1 via
     `ObjectTools.set_properties`, connected to `MP_BaseColor` via `connect_to_output`,
     recompiled, saved.
2. **Actor**: `SceneTools.add_to_scene_from_class` with `/Script/Engine.StaticMeshActor`,
   name `TycoonCube`, location (0,0,100), snap to ground.
   Result ref: `...:PersistentLevel.StaticMeshActor_UAID_74563C41925DDAF902_1295502816`.
3. **Cube component**: `PrimitiveTools.add_cube` on the actor
   (mesh `/Engine/BasicShapes/Cube.Cube`, default 100cm).
4. **Material applied**: `ObjectTools.set_properties` on the cube component with
   `overrideMaterials=[{"refPath":"/Game/M_Block_Red.M_Block_Red"}]` → verified via
   `get_properties`.
5. **Save**: `SceneTools.save_actor` returned null (no-op), `AssetTools.save_assets([])` → true.
6. **Viewport confirmation**: `FocusOnActors` + `CaptureViewport` returned `labeledActors`
   metadata confirming `TycoonCube @(0,0,1)` at screen centre, distance 129cm.

## 5. Notable capability gaps found first-hand

- **No Blueprint-asset factory tool.** No toolset exposes a "create Blueprint asset"
  operation (no equivalent of UE 5.8's `BlueprintTools`), and `ValkyriePythonToolset` only
  exposes `IsPythonEnabledInUEFN` / `EnablePythonInUEFN` — **no arbitrary Python execution**.
  So a literal reusable Blueprint `.uasset` cannot be created over MCP in this build.
  Workaround used: build as placed scene actors (StaticMeshActor + primitive component +
  material), or use Verse Scene Graph entities.
- `ValkyrieToolset.EntityToolset.DeleteEntity` refused on the Scene Graph root entity
  (`"Cannot delete the root entity."`) — a leftover empty entity is harmless.
- The Scene Graph entity path did **not** expose a mesh or colour property on its
  `mesh_component_0` — the scene-actor path was more productive.
